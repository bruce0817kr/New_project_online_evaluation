# Evaluation System Project Rules

이 문서는 AI 조수(Claude)가 코드를 생성하거나 수정할 때 반드시 준수해야 할 원칙입니다.

## 1. Security & Integrity

### 데이터 보호
- **제출 완료된 평가 데이터 보호**: 모든 제출된(is_submitted=True) 데이터는 관리자 권한 없이 수정 불가능합니다.
- **PDF 보안**: PDF 파일은 직접 URL 노출을 금지하며, Stream 방식을 통해 뷰어에 전달합니다.
- **개인정보 암호화**: 개인정보 및 기업 기밀 데이터는 DB 내 암호화 처리를 원칙으로 합니다.

### 감사 추적
- 모든 평가 점수 수정은 `audit_logs` 테이블에 기록되어야 합니다.
- IP 주소, User Agent, 변경 내용을 포함한 상세 로그를 남깁니다.

## 2. UI/UX Principles

### Split-View 구현
- **독립적 스크롤**: 서류 영역과 입력 영역의 스크롤은 독립적으로 작동해야 합니다.
- **고정 레이아웃**: 화면 크기 변경 시에도 2분할 레이아웃이 유지되어야 합니다.
- **반응형 디자인**: 모바일은 상하 분할로 전환합니다.

### Auto-Save 기능
- **자동 저장 주기**: 모든 입력값은 유저의 명시적 클릭 없이도 3~5초 간격으로 자동 저장됩니다.
- **Debounce 적용**: 연속된 입력에 대해 마지막 입력 후 일정 시간이 지난 후 저장합니다.
- **시각적 피드백**: 저장 중, 저장 완료 상태를 명확히 표시합니다.

### Accessibility
- **폰트 크기**: 최소 14px 이상의 읽기 편한 폰트 크기를 사용합니다.
- **명확한 대비**: 버튼과 배경의 색상 대비를 명확히 하여 가독성을 보장합니다.
- **키보드 내비게이션**: Tab 키를 통한 양식 이동이 가능해야 합니다.

## 3. Data Logic

### 점수 계산 규칙
- **반올림 처리**: 점수 계산 시 소수점 셋째 자리에서 반올림 처리합니다.
- **최고/최저점 제외**: 5인 이상의 심사위원이 평가한 경우, 최고점 1개와 최저점 1개를 제외한 평균을 계산합니다.
- **가중치 적용**: 평가 항목별 가중치를 정확히 적용하여 최종 점수를 산출합니다.

### OCR 데이터 처리
- **OCR 추출 실패 시**: 사용자가 수동으로 수정할 수 있는 UI를 반드시 포함합니다.
- **신뢰도 표시**: OCR 추출 데이터의 신뢰도를 표시하여 검증이 필요한 항목을 강조합니다.
- **재시도 기능**: OCR 실패 시 재시도할 수 있는 기능을 제공합니다.

## 4. API Design

### RESTful 원칙
- **명확한 엔드포인트**: 리소스 중심의 명확한 URL 구조를 사용합니다.
- **HTTP 메서드**: GET(조회), POST(생성), PATCH(부분 수정), DELETE(삭제)를 적절히 사용합니다.
- **상태 코드**: 적절한 HTTP 상태 코드를 반환합니다.

### 에러 처리
- **명확한 에러 메시지**: 사용자가 이해할 수 있는 명확한 에러 메시지를 제공합니다.
- **에러 로깅**: 모든 에러는 서버 로그에 기록되어야 합니다.
- **재시도 전략**: 네트워크 에러 등 일시적인 문제에 대한 재시도 로직을 포함합니다.

## 5. Testing Requirements

### Unit Tests
- **핵심 로직 테스트**: 점수 계산, OCR 데이터 추출 등 핵심 비즈니스 로직은 반드시 테스트 코드를 작성합니다.
- **테스트 커버리지**: 최소 70% 이상의 코드 커버리지를 유지합니다.

### Integration Tests
- **API 엔드포인트 테스트**: 모든 API 엔드포인트는 통합 테스트를 작성합니다.
- **데이터베이스 트랜잭션**: 테스트 후 데이터베이스 상태를 원복합니다.

## 6. Performance

### 최적화
- **쿼리 최적화**: N+1 쿼리를 방지하고 적절한 인덱스를 사용합니다.
- **캐싱**: 자주 조회되는 데이터는 캐싱을 고려합니다.
- **파일 처리**: 대용량 PDF 파일은 청크 단위로 처리합니다.

### 모니터링
- **응답 시간**: API 응답 시간을 모니터링하고 3초 이상 소요되는 경우 최적화합니다.
- **OCR 처리 시간**: OCR 처리는 비동기로 처리하고 진행 상황을 사용자에게 표시합니다.

## 7. Code Style

### Python (Backend)
- **PEP 8**: Python 코드는 PEP 8 스타일 가이드를 따릅니다.
- **Type Hints**: 함수 매개변수와 반환값에 타입 힌트를 사용합니다.
- **Docstrings**: 모든 public 함수와 클래스에 docstring을 작성합니다.

### JavaScript/React (Frontend)
- **ESLint**: ESLint 규칙을 준수합니다.
- **함수형 컴포넌트**: 클래스 컴포넌트 대신 함수형 컴포넌트와 Hooks를 사용합니다.
- **명확한 네이밍**: 컴포넌트와 함수는 명확하고 설명적인 이름을 사용합니다.

## 8. Git Workflow

### Commit Messages
- **명확한 메시지**: 변경 내용을 명확히 설명하는 커밋 메시지를 작성합니다.
- **형식**: `[타입] 간단한 설명` 형식을 사용합니다. (예: `[feat] 평가 점수 자동 계산 기능 추가`)

### Branch Strategy
- **기능 브랜치**: 새로운 기능은 별도의 브랜치에서 개발합니다.
- **코드 리뷰**: 모든 변경사항은 PR을 통해 리뷰를 받습니다.
